Muscle memory for AI. Solve it once in Temper, and every language remembers.

One command line, the same in seven languages.

Declare a program’s options, arguments, and subcommands once, and Argmas parses them, writes the help, explains mistakes, and completes them in the shell, with the same behavior in C++, C#, Java, JavaScript, Lua, Python, and Rust. A tool rewritten in another language keeps its command line, down to the last error message.

Argument styles

Unix tools write --verbose, Go’s write -verbose, and Windows tools write /verbose. A command picks its style, and the same declaration parses, writes help, and reports mistakes that way. Here is one frob in all three:

Windows names ignore case, as Windows tools do, and a tool moving from one style to another can accept both with alsoStyle. The design notes have every rule.

Subcommands

Subcommands are commands of their own, with their own arguments, help, and errors, as in git add. An option marked inherited works before or after a subcommand’s name. Other options of the parent go before it, and if one comes after, the error says where it belongs instead of guessing at a near miss.

Shell completions

Pressing Tab in bash, zsh, fish, or PowerShell runs a short script that asks the program itself what could come next. Argmas answers from the same declaration it parses with, so completions always match what the program accepts, values included, and never need regenerating.

Pressing Tab, in a shell that shows descriptions

What the shells get

Each Tab runs frob __complete with the position of the word being completed and the words so far. Argmas answers with one candidate a line, each with a tab and its description, if it has one, and last what else the shell should do, such as list files.

Messages and translations

Everything Argmas writes itself, from Usage: to each error and suggestion, comes from one table of messages, English unless the program sets its own. Each message has a stable key and named placeholders, so a translation can put them in its own order, and a key left out stays English. The program’s own text, such as its options’ help, is the program’s to translate.

A typo in a key is caught on the first run:

The design notes list every key with its English text. Argmas never guesses the user’s language; the program picks a table, as the README shows.

Errors are values

Parsing never prints, exits, or throws. It returns one of three values: Args, to run with; Output, help or a version to print before exiting with status 0; or ArgError, a mistake to print to standard error before exiting with status 2. Nothing outside is touched: the program passes the arguments and, for environment variables, an Environment. That makes a command line easy to test, and easy to embed in a program that isn’t a command-line tool.

  • One behavior to learn. A team with tools in several languages gets one set of rules for --, bundled flags, negative numbers, and option values, instead of each library’s own.
  • One set of docs. Help and errors read the same in every language, so documentation, tutorials, and scripts written for one version of a tool fit the others.
  • Tested once, in every language. Argmas’s tests run on all seven, and CI checks that the tour prints exactly the same in each, and that completions work in real shells on Linux, macOS, and Windows.
  • Port without surprises. Rewriting a tool in another language keeps its command line, so nobody’s scripts break.

Get started

Argmas isn’t released yet. There are no packages to install, and it’s built with Temper’s new compiler, which isn’t released either. For now, build the compiler from source at the commit Argmas’s CI pins (see test.yml), then build Argmas for your language and depend on it by path, as each tour does:

docs/languages.md shows what the API looks like in each language, and what still reads awkwardly there.

Argmas is open source, at github.com/temperlang/argmas, under Apache-2.0 or MIT. Read the design notes for how each corner case is decided.
